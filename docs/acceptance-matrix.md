## 优先级与测试门槛

1. **P0 本轮：** 四份设计文档、版本/来源核查、接口/状态/七表/重启收敛冻结。只可判“设计完成”，不可判功能通过。
2. **P1 后端：** R-01、R-02、R-03 的 Java 部分及 R-04～R-06、R-10 的核心链路先通过测试；三阶段和失败中断是硬门槛。
3. **P2 前端：** R-03、R-07～R-09、R-11；多任务交错响应与请求异常区分是硬门槛。
4. **P3 工程：** R-12、R-14；CI 与真实容器启动分别记录，源码存在不能代替运行通过。
5. **P4 交付：** R-13；README 完成声明、验证记录、实际投入和来源一致。

运行前不能填写“通过”。若环境缺少 Docker、依赖下载失败或素材不可用，分别记录阻碍、源码证据与未验证范围，不能把“未验证”写为“未实现”或“已通过”。
